# Replace the corner hamster with a cat that lives in a cardboard box

## 1. Original issue

> push the box cat to main, take decisions on your own.

Context, from the conversation that produced the work (not part of the issue): the owner asked to change the hamster to something else, chose a cat and a full rename, disliked the first cat's look and picked the "bold-outline sticker" art style, then picked the "box cat" model from a page of eleven cat models. The work sat uncommitted in the local checkout of `main` (13 changed files). "Take decisions on your own" delegates the tier confirmation, the approach approval and the slice review to me; each decision is recorded below.

## 2. What this change does

Before: a golden hamster sits bottom-left. Click feeds it; it puffs its cheeks and, every fifth feed, waddles off to "stash" the food. The terminal has a `hamster` command and the status footer has a "Hamster" row.
After:  an orange tabby sits in a cardboard box, drawn as a sticker (dark ink outline, flat colour, white die-cut edge). It keeps every behaviour: eyes follow the cursor, treats are fish, shrimp and a drumstick, cheeks puff per feed, the fifth feed sets off zoomies (the whole box scoots and turns), it sleeps 23:00-06:00 in a nightcap, and it wears a hard hat, sunglasses, a laptop or an envelope for the section and theme. The terminal command is `cat`, the footer row says "Cat", and the counter's storage key is `portfolio-cat-fed-daily`.

Visitors see a different animal and a slightly different box-shaped silhouette. Nothing else on the site changes. Anyone who fed the hamster today sees the counter start again from 0 once.

### Approach

Approved by me on the owner's instruction to decide on my own.

1. **One commit for everything.** Simplest history. Rejected: it mixes a mechanical rename (13 files, reviewable by grepping) with a redraw (two files, reviewable by eye), so neither review is honest.
2. **Two commits: rename first, then the box cat (chosen).** The rename commit is provably mechanical (`git grep` finds no old names left) and keeps the old hamster art, so it builds and runs on its own. The art commit then touches only `Cat.tsx` and `globals.css`. Costs one intermediate state in which a hamster drawing is named "cat"; it never ships alone because both go to `main` together.
3. **Keep `hamster` identifiers and change only the art.** Smallest diff. Rejected: the code would say hamster over a cat, and the owner chose "full swap".

Decisions taken without asking, each reversible in one commit:
- The terminal command is `cat` and there is no `hamster` alias.
- The storage key is renamed, so the count resets once per visitor.
- The fifth-feed move is zoomies (a whole-box scoot and turn), because cats do not stash food in their cheeks. The cheek puff stays as an outlined bubble that gets more solid per feed.
- Delivery: the owner said "push to main", so the branch is fast-forwarded onto `main` with no PR and no force. If `main` is protected or has moved, fall back to pushing the branch and opening a PR.

## 7. Risks and rollback

- **Risk:** a visitor who types `hamster` gets "command not found" -> **Mitigation:** `help` and the example chip list `cat`; the terminal never echoes typed input, so nothing else can break.
- **Risk:** today's counter resets once because the storage key changed -> **Mitigation:** it is a per-day joke counter that resets at midnight anyway; the old key is simply never read again.
- **Risk:** the box is a wider silhouette than the hamster and could sit on top of content -> **Mitigation:** the dock is the same 168px (124px on phones) and `Contact` already reserves room below its last row; check 6 measures the phone case.
- **Risk:** the merge with PR #4 (`Contact.tsx`, `content.ts`) hides a semantic conflict -> **Mitigation:** the build and check 4 run on the merged tree; the phone number is not reintroduced (`git grep` for the phone-number strings is part of the personal-data guard).
- **Rollback:** `git revert` the two implementation commits (newest first). No data migration is involved, so the revert is safe by itself; visitors' counters would reset once more. If the push lands on `main`, revert on a branch and open a PR.

## 10. Post-implementation

**Post-implementation confidence: 80/100** (pre was 74, delta +6)

**What moved it:** the two unknowns named in section 8 were resolved by evidence, not by feel. The phone-width and reduced-motion cases now have passing checks (5.7b: dock 124px inside a 400px viewport; 5.7c: animation duration under 10ms). The merge with PR #4 applied cleanly (`git apply --3way`, no conflicts) and the build and the phone-number grep run on the merged tree. The verification can now distinguish fixed from unfixed: the same script passes 28/28 on the branch and 2/28 on `origin/main`, and fails when the box front is deleted. The count logic matches the old module on 66 inputs.

**What implementation taught:**
- Three defects in my own check script surfaced and were fixed: a selector that counted the sunglasses' glint rects as lenses, a terminal check that read a log still holding an earlier echoed command (which let 5.8b pass on the hamster site by accident), and a session check that ignored the counter carrying over from the previous session.
- One environment effect looked like a product bug and was not: after keyboard input, the headless page lost focus and was throttled, so `requestAnimationFrame` stopped and timers slowed to one a second. That froze the scroll-spy (props stuck) and delayed the fifth-feed timers. Diagnosis: a rAF promise never resolved. Fix in the script only: `Emulation.setFocusEmulationEnabled` plus `Page.bringToFront`. `useActiveSection.ts` and the feed timers are unchanged.
- The rename slice built and linted on its own with the old drawing, so the two implementation commits are independently revertable.

**What is still unknown:**
- Only Chromium (Edge) was used. Safari and Firefox have not rendered the artwork (SVG `feDropShadow` on animated groups is the item to watch on iOS), and phone width was emulated, not seen on a device.
- `box-cat-check.mjs` lives in the quest scratchpad, not in the repo (the repo has no test runner and adding one is a dependency), so there is no regression test in the repo after this lands.

**Delivery:** the owner said "push the box cat to main". The branch is fast-forwarded onto `main` with no force and no PR. The owner's local `main` still carries its own unpushed commit `20318e2` (tree-identical to `origin/main`'s `b38a7ba`) and an uncommitted copy of this change.
